# WPI (Weight Propagation Interface) with DRA - Demo & Talking Script

## Goal of the Demo
To demonstrate that WPI, powered by Kubernetes Dynamic Resource Allocation (DRA), allows Kubernetes to treat GPU VRAM and Model Weights as first-class scheduling resources. It manages the high-speed transfer of Model Weights across the network *independently* of the CPU, completely bypassing traditional storage latency, and enables zero-copy consumption by Inference Pods.

## Prerequisites
Have 3 terminal windows or panes open side-by-side:
1. **Terminal 1 (Top Left):** Ready to execute Kubernetes YAMLs and the WPI benchmark script.
2. **Terminal 2 (Bottom Left):** Running `watch kubectl get pods,resourceclaims,resourceclasses -A` to show DRA resource states and pod status.
3. **Terminal 3 (Right):** Running `htop` and `nvtop` on either the source or target node to monitor CPU vs Network/GPU utilization.

## The Script

### 1. Introduction: The Problem with Traditional Model Loading
**[Action - Terminal 1]** Clear the screen. Ensure no pods are running.

**[Speaker - Talking Script]:** 
"Today, we're demonstrating the Weight Propagation Interface, or WPI, leveraging Kubernetes Dynamic Resource Allocation (DRA). 

Currently, if you want to move a large foundational model, say 75GB, from a Training Node to an Inference Node in Kubernetes, you write it to a persistent disk or a GCS bucket. The Inference Pod then has to download it over the network to the host, and then load it from the host memory into the GPU VRAM.

This means your Inference Pod sits in the `Init` state for minutes. It ties up your CPU, and your expensive GPUs sit idle at 0% utilization while they wait for data.

WPI solves this by using Kubernetes DRA to treat Model Weights and VRAM as native Kubernetes resources—just like a persistent volume, but for GPU memory."

### 2. The Solution: DRA and WPI CRDs
**[Action - Terminal 1]** `cat demo_weight_claim.yaml` (Show the WeightClaim YAML)

**[Speaker - Talking Script]:** 
"Instead of downloading files, the Inference Engineer simply creates a `WeightClaim`. Because we are using DRA, this is analogous to a PersistentVolumeClaim, but it asks for a specific `WeightBuffer` that was just generated by the Training node.

This tells the Kubernetes Scheduler and the WPI Operator exactly what VRAM resources are needed *before* the pod even starts. Kubernetes reserves the memory and triggers the data plane."

### 3. Executing the Data Plane (The Propagation)
**[Action - Terminal 3]** Point the audience to the `htop` and `nvtop` monitors on the right.
**[Action - Terminal 1]** Execute `./benchmark.sh` (or apply the propagation job).

**[Speaker - Talking Script]:** 
"Let's trigger the actual fabric propagation that the WPI driver handles under the hood to fulfill this DRA claim. Keep an eye on the CPU utilization on the right.

The WPI driver is now allocating the memory directly on the target GPU and streaming the weights across the RDMA/PCIe network using NCCL. 

Notice the CPU? It's completely flat at near 0%. We are bypassing the host processor entirely. Yet, we are moving data at..."

**[Action - Terminal 1]** Wait for `./benchmark.sh` to output the final throughput.

**[Speaker - Talking Script]:** 
"...nearly 40 Gigabytes per second! We just moved a 75GB foundational model across the network in literally 2 seconds directly into the VRAM."

### 4. The Inference Pod Consumer (Zero-Copy)
**[Action - Terminal 1]** `cat demo_inference_pod.yaml`
**[Action - Terminal 2]** Point out the `ResourceClaim` allocated status.

**[Speaker - Talking Script]:** 
"Now that the data is staged in the target's VRAM through DRA, what does the application developer experience? 

They deploy a standard Inference Pod. In the Pod spec, they reference the `ResourceClaim`. Because the WPI Operator and DRA have already pre-staged the weights into the GPU during scheduling, when this pod starts, it doesn't download anything. 

The WPI driver securely passes a unified memory file descriptor to the Pod. The Pod just maps the memory pointers."

**[Action - Terminal 1]** `kubectl apply -f demo_inference_pod.yaml`
**[Action - Terminal 2]** Show it instantly hitting `Running`.

**[Speaker - Talking Script]:** 
"The pod goes from pending to generating tokens almost instantly. 

By integrating WPI with Kubernetes DRA, we've decoupled the AI Data Plane from the Compute Lifecycle, eliminating cold starts and maximizing GPU utilization from second zero."
